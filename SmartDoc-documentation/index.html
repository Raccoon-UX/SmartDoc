01. Overview & Vision

SmartDoc Overview

[IMPLEMENTED] Production Ready Vite 6 + React 18 + Supabase

SmartDoc is a centralized public service discovery platform and secure digital document management system designed to eliminate civic administrative friction in India. It bridges the gap between citizens navigating fragmented departmental websites and the official sovereign platforms required to execute identity, civic, and financial document services.

Core Value Proposition

"SmartDoc helps citizens find the right document service, understand exact requirements and fees before applying, and safely reach the authentic official platform while providing a private, encrypted vault to manage personal document copies."

High-Level System Overview Diagram

1
Public Discovery Layer (Client Browser)
Universal Autocomplete Search, 34+ Curated Sovereign Service Catalog, Pre-requisite Checklists, Anti-Phishing Guidance
↓
2
Direct Sovereign Platform Redirection
Direct deep links to audited government endpoints (UIDAI, Protean PAN, Passport Seva, Parivahan, NVSP, DigiLocker)
↓
3
Authenticated Personal Document Vault (PostgreSQL + Supabase Storage)
JWT-authenticated user sessions, Row Level Security (RLS) data isolation, private bucket uploads, short-lived signed previews
02. Problem Statement

The Civic Document Dilemma

Navigating public document services in modern India presents five distinct pain points for citizens and residents:

Challenge Area Real-World Citizen Problem SmartDoc Architectural Solution
Fragmented Portals Civic services are spread across dozens of state and central websites with non-standard URLs and broken redirects. Centralized search directory indexing 34+ core public documents and services with instant keyword search.
Opaque Requirements Citizens often visit service centers or start online forms without knowing mandatory proof documents, leading to application rejection. Pre-formatted, interactive, and printable prerequisite checklists with required proofs and statutory fee breakdowns.
Phishing & Clones Search engines frequently rank ad-heavy third-party clone websites that charge exorbitant fees or harvest sensitive Aadhaar/PAN data. Strictly verified sovereign platform links with government domain badges (.gov.in / .nic.in) and safety advisories.
Scattered Documents Personal scanned copies of passports, marksheets, and utility bills are lost in chat histories and email threads. Encrypted personal document vault with category tagging, instant filtering, and secure cloud storage.
03. Principles

Objectives & Design Principles

1. Radical Clarity

No bureaucratic jargon. Every document page outlines exact processing turnaround, statutory fees, and step-by-step application flows.

2. Sovereign Integrity

SmartDoc never acts as an unverified middleman. Citizens are redirected directly to authoritative government portals.

3. Zero Data Compromise

User files are isolated via PostgreSQL Row Level Security (RLS) and stored in private non-public S3-compatible buckets.

4. Universally Responsive

Engineered from 320px mobile viewports up to 1440px+ 4K displays with accessible touch targets (≥ 40px).

06. Discovery

Service Discovery Engine

[IMPLEMENTED]

The service discovery engine operates on structured in-memory catalogs (src/data/documents.ts and src/data/services.ts) containing rich metadata for 34+ civic documents.

Catalog vs. Static UI: Document details, requirements, fees, issuing authorities, and official URLs are 100% data-driven. Filtering and search happen in real-time on the client using URL query parameters (?q=...&category=...).
07. Auth Architecture

Authentication & Account Management

[IMPLEMENTED]

Authentication is powered by Supabase Auth with JWT session persistence in localStorage. The application wraps all views with an AuthContext provider that synchronizes user sessions and database profile records.

TypeScript — Auth Context Provider Flow 
// Session Initialization in AuthContext.tsx
supabase.auth.getSession().then(({ data: { session } }) => {
  setSession(session);
  if (session?.user) {
    fetchProfile(session.user.id, session.user.email);
  }
});

// Real-time Auth State Change Listener
supabase.auth.onAuthStateChange((_event, newSession) => {
  setSession(newSession);
  if (newSession?.user) {
    fetchProfile(newSession.user.id, newSession.user.email);
  } else {
    setUser(null);
  }
});

09. Upload Pipeline

Document Upload Pipeline

[IMPLEMENTED]
1
Client File Validation: Verify MIME type (PDF, PNG, JPG) and enforce ≤ 10 MB size limit (fileValidation.ts).
2
UUID & Storage Path Creation: Construct secure path <user_id>/<doc_id>/<sanitized_name>.
3
Encrypted Object Storage: Stream binary to private S3 bucket user-documents with non-public ACLs.
4
Metadata Insertion & Atomic Rollback: Insert document metadata in PostgreSQL. If database insert fails, auto-delete uploaded storage object to prevent orphan files.

15. Database Architecture

Database Entities & Storage Schema

[IMPLEMENTED]
SQL — PostgreSQL Table Schema (01_phase3_init.sql) 
-- 1. Profiles Table
CREATE TABLE public.profiles (
  id UUID REFERENCES auth.users(id) ON DELETE CASCADE PRIMARY KEY,
  full_name TEXT,
  email TEXT,
  avatar_url TEXT,
  created_at TIMESTAMPTZ DEFAULT timezone('utc'::text, now()) NOT NULL,
  updated_at TIMESTAMPTZ DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- 2. User Documents Metadata Table
CREATE TABLE public.documents (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE NOT NULL,
  name TEXT NOT NULL,
  category TEXT NOT NULL DEFAULT 'other',
  document_type TEXT NOT NULL DEFAULT 'pdf',
  description TEXT,
  file_path TEXT NOT NULL,
  file_name TEXT NOT NULL,
  file_size BIGINT NOT NULL DEFAULT 0,
  mime_type TEXT NOT NULL,
  issue_date DATE,
  expiry_date DATE,
  issuing_authority TEXT,
  notes TEXT,
  created_at TIMESTAMPTZ DEFAULT timezone('utc'::text, now()) NOT NULL,
  updated_at TIMESTAMPTZ DEFAULT timezone('utc'::text, now()) NOT NULL
);
16. Security

Row Level Security (RLS) & Policies

SmartDoc implements server-enforced PostgreSQL Row Level Security (RLS) across all tables and storage buckets:

  • auth.uid() = user_id on public.documents for SELECT, INSERT, UPDATE, DELETE.
  • auth.uid() = id on public.profiles for SELECT, INSERT, UPDATE.
  • (storage.foldername(name))[1] = auth.uid()::text on storage.objects to strictly lock bucket access to user root folders.
  • Short-lived signed URLs (expiresInSeconds: 300) for in-browser file previews.

18. Workflows

End-to-End User Workflows

Workflow: Document Upload to Encrypted Vault 
User clicks "Upload Document" -> Drag/Select File (PDF/PNG/JPG <= 10MB)
  -> Client validates file signature & size
  -> Calls uploadVaultDocument() in vaultService.ts
  -> Uploads binary to private S3 bucket: user-documents///
  -> Inserts metadata record in PostgreSQL 'documents' table
  -> Returns new VaultDocument object to React state
  -> Displays toast notification "Document uploaded successfully!"
  -> Dashboard stats & storage gauges re-calculate instantly

21. Services

Client Services & Data Flow

25. Limitations

Known Project Boundaries

  • Static Service Catalog: Catalog entries are curated in TypeScript data files rather than dynamically polled from government APIs.
  • Client-Side Filtering: Catalog search runs in browser memory; suitable for current catalog size (34+ entries).
  • No Native OCR: Scanned files are stored as raw binaries; automated text extraction is scoped for future phases.

32. FAQ

Frequently Asked Questions

Is SmartDoc an official government portal?

No. SmartDoc is an independent public discovery tool and personal document vault that guides citizens to authentic official government portals.

Can anyone else see the documents I upload?

No. All uploaded documents are strictly protected by Row Level Security (RLS) policies and private storage buckets tied exclusively to your authenticated user account.
